# KREODA — MINIMAL CONTEXTUAL UI REFACTOR

## Obiettivo

Ridisegnare l'interfaccia desktop di Kreoda seguendo una filosofia:

> viewport-first, progressive disclosure, direct manipulation, context-first UI.

Il risultato deve riprendere il concept approvato:

* viewport 3D quasi a tutto schermo;
* pochissima UI permanente;
* barra principale flottante in alto;
* progetto/logo negli angoli;
* Undo/Redo/Salva separati;
* command/AI bar flottante in basso;
* azioni contestuali vicine alla geometria selezionata;
* quote modificabili direttamente nel viewport;
* pannelli laterali normalmente nascosti;
* strumenti avanzati disponibili tramite progressive disclosure;
* modalità Sketch coerente con la stessa UI;
* look dark premium, molto pulito, accenti blu.

Questa roadmap è un track UI indipendente.

NON rinominare o sovrapporre le Phase 10–16 esistenti.

Usare i nomi:

* UX-0
* UX-1
* UX-2
* UX-3
* UX-4
* UX-5

Alla fine di ogni fase:

1. eseguire i test pertinenti;
2. correggere tutte le regressioni causate dalla fase;
3. produrre un `UX-N COMPLETION REPORT`;
4. FERMARSI;
5. non iniziare la fase successiva fino alla review.

# REGOLE NON NEGOZIABILI

## Architettura

Non modificare la proprietà dello stato CAD.

Rimane:

```text
OCCT/core
    ↓
canonical CAD state
    ↓
React = UI projection only
Three.js = viewport only
```

Non spostare CAD state dentro React.

Non creare geometria CAD direttamente nel renderer.

Non cambiare il principio preview → commit.

Una manipolazione continua deve continuare a produrre un solo Undo al commit.

Tutte le operazioni devono continuare a passare da:

```text
packages/command-schema
apps/desktop/src/commands/execute.ts
```

Non creare percorsi alternativi solo per la nuova UI.

## Funzionalità reali, non mock

NON implementare pulsanti che sembrano funzionanti ma non hanno un comando reale.

Il concept visivo contiene esempi come:

```text
Sposta
Ruota
Scala
Elimina
Materiale
```

ma la UI reale deve esporre soltanto ciò che Kreoda supporta realmente.

Attualmente il registry supporta tra gli altri:

```text
CreateBox
CreateCylinder
CreateSphere
CreateSketch
CreateExtrude
CreateHole
CreateHolePattern
CreateFillet
CreateChamfer
CreateBoolean
CreateInstance
SetDimension
Undo
Redo
```

`CreateInstance` supporta trasformazioni dell'istanza.

Non trasformare questa fase UI in una fase di implementazione di nuovi strumenti CAD.

Se una funzione del concept non esiste realmente, non mostrarla come disponibile.

## Test

Non eliminare test per far passare il refactor.

Non indebolire assertion CAD.

È consentito aggiornare locator/test UI quando la UI è stata intenzionalmente modificata.

Preferire progressivamente:

```text
data-testid
aria-label
semantic roles
```

agli assert basati sul testo visualizzato.

La geometria, revisioni, Undo/Redo e command execution devono mantenere le assertion esistenti.

# UX-1 — MINIMAL WORKSPACE SHELL

## Obiettivo

Portare la shell principale alla struttura del concept senza ancora cambiare profondamente l'interazione contestuale.

La struttura desiderata è:

```text
┌─────────────────────────────────────────────────────────┐
│ KREODA             floating tools           ↶ ↷  Salva │
│ project                                                 │
│                                                         │
│                                                         │
│                    3D VIEWPORT                          │
│                                                         │
│                                                         │
│              AI / COMMAND BAR                           │
│              contextual suggestions                     │
│                                                         │
│ Snap / Grid                                      ? ⚙    │
└─────────────────────────────────────────────────────────┘
```

Il viewport deve occupare praticamente tutta la finestra.

## Rimuovere dalla presenza permanente

L'attuale:

```text
ObjectTree sempre aperto
PropertiesPanel sempre aperto
toolbar orizzontale enorme
status/history footer permanente
selection filters permanenti
```

non deve più consumare spazio continuamente.

Non eliminare le funzionalità: renderle richiudibili o contestuali.

## Nuova shell

Creare componenti dedicati invece di trasformare `App.tsx` in un monolite.

Indicativamente:

```text
components/workspace/
  WorkspaceChrome.tsx
  TopToolDock.tsx
  ProjectChip.tsx
  WorkspaceActions.tsx
  BottomCommandDock.tsx
  WorkspaceStatus.tsx
```

I nomi possono essere adattati se necessario.

### Alto sinistra

Logo Kreoda.

Sotto o accanto:

```text
nome progetto/documento
stato modifiche se disponibile
```

Il project chip deve poter aprire successivamente il Project Drawer.

### Alto centro

Solo:

```text
+ Aggiungi
Sketch
Misura
Altro
```

Usare icone Lucide.

Non mostrare direttamente box/cylinder/sphere ecc.

`Aggiungi` apre popover:

```text
Box
Cilindro
Sfera
...
```

basato sul command registry.

### Alto destra

```text
Undo
Redo
Salva
```

Salva deve mantenere il comportamento reale esistente.

### Basso centro

Refactor del `CommandBar`.

Deve sembrare la command bar del concept:

```text
✦  Dimmi cosa vuoi fare...               🎙 / →
```

Il microfono NON deve essere mostrato come attivo se non esiste STT.

Può essere omesso o disabled con motivazione accessibile.

Sotto, piccole suggestion chips.

Riutilizzare parser e provider esistenti.

Non creare un secondo command system.

### Basso sinistra

Stato minimal:

```text
Snap
Griglia
```

Solo se realmente applicabili.

Se oggi non sono configurabili, evitare controlli finti.

### Basso destra

```text
Impostazioni
Aiuto
```

possono aprire popover/drawer reali o restare fuori da UX-1 se non esistono ancora.

## Object Tree e Properties

Per questa fase possono continuare ad esistere internamente, ma non devono essere visibili permanentemente.

## Recovery / crash

I banner di recovery/crash devono continuare a funzionare.

Non nascondere errori critici dietro UI decorativa.

## Acceptance UX-1

A 1920×1080 il viewport deve utilizzare almeno circa l'85% dell'area utile.

A 1366×768 la UI non deve sovrapporsi in modo distruttivo.

Tutti i command path precedenti devono funzionare.

Undo/Redo/Save funzionanti.

Command bar funzionante.

Add primitive funzionante.

Nessuna modifica al CAD core.

Produrre screenshot E2E della nuova shell.

Report e stop.

# UX-2 — CONTEXTUAL MODELING UI

## Obiettivo

Questa è la fase centrale.

Quando l'utente seleziona geometria, la UI rilevante deve apparire vicino alla selezione anziché in un pannello fisso.

## ContextToolbar attuale

Attualmente `ContextToolbar.tsx` compare in posizione fissa top-center.

Refactorarla in una floating contextual toolbar ancorata alla selezione nel viewport.

Usare `@floating-ui/react`, già presente nelle dipendenze, oppure una soluzione equivalente pulita.

## Selection anchor

NON usare coordinate hardcoded.

Esiste già l'infrastruttura necessaria:

```text
viewportProjectPoint()
faceCentroid()
DimensionChips
CadViewport.projectPoint()
```

Estrarre la logica condivisa in una utility/hook, ad esempio:

```text
interaction/selectionAnchor.ts
```

o equivalente.

Deve produrre una posizione viewport affidabile per:

```text
face
edge
body
sketch quando applicabile
```

Per le face si può riutilizzare centroid + projection.

Per body, calcolare un anchor visuale dal bounding box/mesh senza alterare il modello CAD.

Nessun React state aggiornato ogni frame.

Seguire lo stesso principio imperativo usato da `DimensionChips`.

## Azioni contestuali

### Faccia

Mostrare solo azioni valide, per esempio:

```text
Tira
Foro
Sketch
Altro
```

La disponibilità continua a provenire dal command registry.

### Bordo

Per esempio:

```text
Raccorda
Smusso
Connessi / Simili dove applicabile
Altro
```

### Sketch

Per esempio:

```text
Estrudi
Modifica
Altro
```

### Due solidi

Mostrare:

```text
Unisci
Sottrai
Interseca
```

### Corpo singolo

Mostrare solo operazioni realmente supportate.

`CreateInstance` può diventare:

```text
Duplica / Copia posizionata
```

Non mostrare Move/Rotate/Scale generici se il modello selezionato non supporta realmente tali comandi.

## Dimension Chips

`DimensionChips.tsx` è già molto vicino alla filosofia target.

Refactor estetico:

da:

```text
amber chips
W/H/D tecnici
```

verso:

```text
dark translucent chip
thin blue outline when active
120 mm
⌀ 35 mm
R 5 mm
```

La modifica inline deve continuare a supportare:

```text
numero
unità
=formula
Enter
Escape
errori inline
```

Non perdere Phase 9 expressions.

## Properties

`PropertiesPanel` non deve più essere sempre presente.

Aprirlo come:

```text
popover
floating card
right drawer
```

solo su richiesta, ad esempio da `Altro → Proprietà`.

Mantiene tutta la capacità di editing attuale.

## Suggestion Bar

Integrare `SuggestionBar` con il bottom command dock.

Esempio:

```text
[ Crea foro da 35 mm ]
[ Uniforma i fori ]
[ Raccorda bordi ]
```

Non deve coprire il modello.

## Acceptance UX-2

Face selection → toolbar appare vicino alla face.

Edge selection → cambia azioni senza toolbar globale piena.

Body selection → niente strumenti fasulli.

Quote modificabili direttamente nel viewport.

Formula dimensions ancora funzionanti.

Select Similar / Connected ancora funzionanti.

Boolean ancora funzionante con due body.

Phase 3 + Phase 6 + Phase 9 relevant tests verdi.

Aggiungere E2E specifico per:

```text
context toolbar follows selection
toolbar actions change with selection kind
properties drawer closed by default
dimension edit from viewport
```

Report e stop.

# UX-3 — SKETCH WORKSPACE

## Obiettivo

Portare anche lo Sketch Editor nello stesso linguaggio UI.

Attualmente `SketchEditor.tsx` è sostanzialmente un editor/modal separato con una propria struttura.

Non deve sembrare un'altra applicazione.

## Target

Quando si entra nello sketch:

```text
Kreoda shell resta riconoscibile
Sketch è evidenziato
viewport passa alla modalità 2D
command bar resta disponibile
quote stanno vicino alla geometria
strumenti sketch appaiono contestualmente
```

Esempio toolbar:

```text
Linea
Rettangolo
Cerchio
Arco
Altro
```

MA mostrare soltanto strumenti realmente implementati.

## Preservare completamente

```text
solver
constraints
drag preview
Escape cancel
release = commit
downstream recompute
one Undo step
conflict reporting
```

Non riscrivere il solver.

Non spostare sketch authority nel renderer.

## Quote

Ridurre la dipendenza dal pannello laterale `Dimensions`.

Quando possibile rappresentare le quote come elementi direttamente attorno allo sketch.

Il pannello completo constraints può essere accessibile tramite:

```text
Altro → Vincoli / Dettagli
```

Non è necessario eliminare subito tutta la UI diagnostica interna, ma deve essere nascosta nella modalità semplice.

## Command bar

In sketch mode i suggerimenti cambiano contestualmente.

Per esempio:

```text
Rettangolo 1200×600
Cerchio Ø35
Chiudi sketch
Estrudi 40 mm
```

solo quando semanticamente validi.

## Acceptance UX-3

Creazione sketch funziona.

Editing delle dimensioni funziona.

Drag point + solve funziona.

Escape durante drag funziona.

Extrude successivo funziona.

Downstream solids si aggiornano.

Phase 4 E2E verde.

Aggiungere screenshot E2E del nuovo sketch workspace.

Report e stop.

# UX-4 — PROGRESSIVE DISCLOSURE / DRAWERS

## Obiettivo

Recuperare tutte le capacità avanzate dell'attuale UI senza sporcare la schermata principale.

## Project Drawer

Click sul project chip apre un drawer contenente:

```text
Objects
Sketches
History
```

Riutilizzare `ObjectTree`.

Non duplicare la costruzione della feature tree.

Drawer chiuso di default.

## Properties Drawer

Contiene l'attuale capacità di `PropertiesPanel`.

Aperto solo quando richiesto.

## Altro

Il menu `Altro` raccoglie funzioni meno frequenti, per esempio quando disponibili:

```text
Plugins
Reference image
Selection filter
Simple / Advanced
Import
Export
Instance placement
diagnostics appropriate to user
```

Non mettere tutto direttamente nel menu principale se può essere raggruppato.

## Simple / Advanced

Il sistema esistente `beginnerMode` deve restare.

Ma non deve essere un grosso pulsante sempre visibile.

Spostarlo in:

```text
Altro
oppure
Settings
```

Simple e Advanced continuano a lavorare sullo stesso modello.

## Onboarding

Ridurre l'attuale onboarding a qualcosa di molto leggero.

Su documento vuoto:

```text
Cosa vuoi creare?

[ Aggiungi una forma ]
[ Disegna uno sketch ]

oppure

Dimmi cosa vuoi creare...
```

Non coprire tutta l'app con istruzioni.

## Status

Revision, mesh count, core version ecc. sono utili per debug ma non devono essere permanentemente nel footer consumer.

Spostarli in:

```text
diagnostics
about
developer/status popover
```

Mantenere sempre visibili solo gli stati che richiedono un'azione dell'utente.

## Acceptance UX-4

Nessuna capacità precedente è stata persa.

Object tree raggiungibile in massimo 1 click.

Properties raggiungibili in massimo 1–2 click dal contesto.

Plugins/Reference/selection mode ancora raggiungibili.

Simple/Advanced ancora funziona.

No sidebars permanenti.

Report e stop.

# UX-5 — VIEWPORT POLISH + FINAL REGRESSION

## Obiettivo

Portare anche il rendering visivo vicino al concept senza trasformarlo in un renderer fotorealistico.

Kreoda rimane un CAD.

## CadViewport

Intervenire solo sul presentation layer:

```text
background
grid
selection color
hover color
mesh material
edge visibility
lighting
anti-aliasing presentation
```

Target:

```text
charcoal workspace
subtle grid
neutral grey solids
blue selected face/body
softer hover
good edge readability
```

Evitare materiali da videogame o rendering pesante.

Il modello deve restare leggibile prima che bello.

## Selection

Usare il blu come colore principale di interazione.

Evitare l'attuale combinazione di molte tonalità amber dove non necessaria.

Warning/error restano semanticamente distinti.

## Performance

Non aggiungere:

```text
React state every pointer move
React state every animation frame
expensive DOM reconstruction every render frame
continuous WebGL render when scene is unchanged
```

Mantenere la filosofia demand-rendering già usata dal viewport.

## Responsive

Verificare almeno:

```text
1366×768
1920×1080
2560×1440
```

## E2E finale

Eseguire:

```bash
pnpm --filter @kreoda/desktop lint
pnpm --filter @kreoda/desktop test
pnpm test:e2e
```

Poi, se l'ambiente lo permette:

```bash
pnpm test:all
```

Non accettare regressioni come “causate solo dalla UI” se rompono un workflow.

## Nuovo visual E2E

Aggiungere un test dedicato, ad esempio:

```text
e2e/workspace-ui.spec.ts
```

Scenari minimi:

```text
empty workspace
body selected
face selected
edge selected
two bodies selected
sketch mode
command plan preview
properties drawer
project drawer
recovery banner
```

Fare screenshot per questi stati.

Non usare pixel-perfect testing fragile come unica assertion.

Le assertion funzionali restano primarie.

## Definition of Done

La nuova UI è conclusa quando:

* il viewport domina visivamente la finestra;
* la UI permanente è minima;
* gli strumenti compaiono quando servono;
* le operazioni frequenti richiedono meno ricerca nei menu;
* le quote sono modificabili vicino alla geometria;
* Sketch e 3D sembrano parti dello stesso prodotto;
* tutte le funzionalità già implementate restano raggiungibili;
* non esistono fake controls;
* non è stato introdotto un secondo command path;
* il CAD core non è stato modificato per ragioni puramente estetiche;
* i principali E2E sono verdi;
* la nuova UI mantiene le garanzie preview/commit/Undo già presenti.

Produrre infine:

```text
KREODA UI REFACTOR FINAL REPORT

Implemented
Architecture changes
Components added
Components removed/refactored
Behavior intentionally changed
Tests updated
Tests added
Full test results
Known limitations
Screenshots produced
Potential follow-up UX work
```

e fermarsi.
