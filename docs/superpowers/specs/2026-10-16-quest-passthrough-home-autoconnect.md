# Quest passthrough Home and automatic PC connection

## User steering, 16 October

Quest UI must appear in passthrough. Initial screen must match the Desktop Home, with the actual room replacing its animated/video background. PC and Quest discover each other on the local network and connect automatically without entering addresses or pairing codes. UI must be clean, minimal and Apple-like. Existing hands-only operation and voice interaction remain required. This supplements the active full Phases12-16 goal and takes priority in the next Quest interaction work; it does not discard the ongoing projection/MCP work.

Existing authorization permits autonomous implementation, installation of necessary software and hidden local work. No additional design approval is required by the user. Current restrictions on Hermes/server access, physical Quest/ADB, microphone/camera/audio and foreground UI remain until explicitly changed. Implement/build locally; do not claim physical acceptance.

## Home and visual design

- Launch directly into Home over the real room. Passthrough preference is true at every normal startup, including upgrade from a saved VR preference. Keep honest diagnostic/fallback on unavailable MR; never label an opaque fallback as working passthrough.
- Use actual Desktop components as the reference: HomeScreen, HomeHero, HomeTopBar, QuickStart, RecentProjects, ActionOrbit, RunningTasks and HomeQuote. Same recognizable hierarchy: KREODA wordmark, Progetta · Visualizza · Realizza / Dalla tua idea al mondo reale; recent projects at left, quick-start actions Nuovo Progetto, Importa, Template, AI Assistant; compact design/view/measure actions and connection status. Desktop wordmark is in its video: Quest needs a real text/vector wordmark because no video/background/GIF/Three.js scenery is rendered.
- Spatial layout adapts the same Home to Quest rather than fitting the existing dense square settings panel. Calm light translucent rounded surfaces, dark readable text, restrained blue accent, generous spacing, minimal separators, soft lightweight depth. No borrowed Apple logos, unlicensed proprietary fonts, heavy glows or expensive full-scene blur. Existing font or properly licensed installed asset is enough.
- One comfortable world-space Home board near eye level; compact workspace toolbar and contextual sheets replace always-visible engineering controls. Preserve panel grab/recenter, both hands, tracking-loss release barrier and existing CAD/datum/section/voice interactions. Every interaction works with tracked hands and pinch without controllers.
- Home stays available before connection with a small Ricerca del PC status. On connection it shows the PC name/status and usable actions. No IP, port or code fields in the normal flow. Technical diagnostics may remain in an advanced sheet.
- Use real available session/project/task state. Desktop currently hardcodes demo recent projects and task content: do not misrepresent these as user files. Until genuine PC Home data is available, show an honest empty/loading state with the same structure; complete real Home actions/data in the integration packet. Never silently wipe an unsaved PC document or fake successful import/template/render.
- Home AI action routes to existing agent/voice UI, never auto-starts microphone or audio. No direct anonymous model API.

## Automatic local connection

- Automatic discovery starts when both apps are running; no manual PC listener setup, token copying, IP entry, QR scan or headset pairing wizard. A single compatible PC connects automatically. Previously trusted stable PC identity wins after IP changes/restart. If several compatible PCs remain ambiguous, show their names for one selection; no code entry. UI asks no question when a unique PC is available.
- Advertise/discover only app presence and stable PC identity on the private LAN. Exchange pairing material automatically through a bounded private-LAN handshake, then reuse existing per-device credentials/authenticate/hello and persisted trust/reconnect. Never broadcast reusable credentials. No internet scanning or Hermes dependency.
- Minimal architecture: a versioned bounded UDP local-discovery request/reply, nonce correlation, PC display name/stable installation ID and advertised session/pair endpoint ports; use packet source address for endpoint derivation. Local HTTP automatic-pair endpoint delegates to the existing SessionDevices credential-creation/persistence path (factor shared creation instead of bypassing hello/transactions). No user-visible codes. Bind CAD session to an assigned private LAN address; preserve loopback/test mode.
- Bound packet/body sizes, retries/backoff and service lifetimes. Expire stale candidates; reject malformed/version-mismatched/non-private packets and endpoints unrelated to the sender. Retain existing credentials across ordinary upgrades/IP changes. Revocation invalidates the current credential, disconnects its sessions and blocks that installation identity from automatic reuse. Do not clear other user configuration.
- Enrollment policy follows the user's explicit instruction that setup must be automatic and initial security limitations are acceptable: private LAN access grants new enrollment without PC confirmation or codes. An explicit local reset/reinstallation with a new identity is a new enrollment under this policy. Do not claim a permanent ban of the physical headset or hardware attestation; a client-supplied identifier cannot provide that. Existing credentials remain protected and revocable. This resolves an ambiguity in the earlier phrase revocation/forget must remain meaningful; it does not add a user approval flow contrary to the requested zero-code setup.
- Credentials and installation identities are distinct for each PC. Switching to B must never send A's secret to B or discard A's working record. Persist B's pending secret separately before bootstrap for idempotent retries; only make B the active saved connection after authentication, hello and a valid snapshot. Keep successful PC records for switching back, preserve the prior active record on any failed/cancelled switch, and retain legacy-file migration and saved-endpoint fallback behavior.
- Background test mode disables real LAN advertising/discovery by default and uses loopback fixtures. Tests must not pair the actual headset or modify live PC trust/firewall. Physical/LAN acceptance is separate from local proof.

## Acceptance

UI: source-backed Home parity, no animated/environment background, passthrough default migration, compact contextual workspace, no ordinary manual-code page, readable non-overlapping text and hands-only selection/drag/release. Editor tests and inspectable offscreen renders, no desktop capture. Saved-scene normal ARM64 build without Prepare workaround; integrated managed sources and build provenance must be stable after the active runtime worker finishes.

Connection: real loopback PC service + managed discovery/bootstrap client -> persisted credentials -> existing session authenticate/hello/snapshot; zero manual inputs. Repeat after service restart and changed endpoint, zero/one/multiple PC cases, malformed packets, bounded receive, cancellation, revocation and no duplicated connection workers. Then hidden Electron integration and Quest Editor/normal ARM64. Real Wi-Fi, headset MR visibility/comfort and hands acceptance remain unverified until permitted. Full goal remains open.
