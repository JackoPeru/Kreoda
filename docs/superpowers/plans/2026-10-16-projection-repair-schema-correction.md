## Recovery architecture amendment

The existing requirement that every Set/Remove immediately rebuild all dependent geometry deadlocks recovery when two existing groups are broken. Clarify the contract: an explicit group repair/removal on a branch that was already unavailable may commit a reversible metadata/binding repair while other pre-existing blockers remain. The branch stays explicitly unavailable throughout; cached B-Rep remains historical and all geometry/mesh/pick/measurement/export/modeling boundaries continue to deny it. This intermediate repair is not published as healthy geometry. Once blockers are resolved, perform the ordinary full native reevaluation/rebuild atomically; failure rolls back that mutation to the preceding inspectable unavailable state. Never allow an ordinary edit of a healthy branch to commit a newly broken branch.

- Set must validate/bind the selected replacement as a valid source definition and reject a failed selected-group evaluation; unrelated pre-existing broken groups may remain inspectable. Do not merely switch allowBroken globally and accept invalid replacements. Keep cycles, limits, owner/context and private-label validation intact.
- Aggregate resource failures remain hard mutation errors even in recovery. In particular, repairing an early group must not consume the2000-edge budget and turn a later healthy group into a newly broken group accepted by allowBroken. Checking only the selected group's status is insufficient; add an atomic overflow regression in an already unavailable sketch with later healthy groups. Do not lower native limits.
- Remove may release just the selected group's binding/dependency while other existing blockers keep the branch unavailable. Removing the last usable profile from a branch with dependent solids still fails when no valid final rebuild is possible. Existing healthy removal/rollback semantics remain.
- Keep partial repair out of ordinary modeling recompute. Update only owned sketch metadata/private bindings/dependencies inside the normal OCAF command and snapshot rollback. Avoid contaminating global dirty state so later unrelated healthy mutations do not recompute and fail the unavailable branch. On final valid repair mark the complete affected closure dirty and rebuild it normally. FeatureGraph.addFeature marks its node dirty; account for that explicitly with existing clearDirty if appropriate. Do not clear unrelated pending work or introduce a general tolerate-all-failures recompute mode.
- Each intermediate/final repair preserves sketch/group/dependent feature IDs, increments the ordinary revision/history once, participates in joined transaction ownership, and survives real .icad save/open plus Undo/Redo. A failed final repair or joined transaction must not leave changed metadata, binding labels, graph, revision or cached shapes.

Required real RED/GREEN: load two broken groups with retained downstream B-Rep; repair one and prove branch still unavailable/no stale query/mesh/measurement; save/open intermediate state; unrelated healthy edit succeeds; repair second and prove same IDs/current analytic native solid. Undo/Redo crosses both repairs. Also remove one of two broken groups, prove source dependency release, and prove last-profile/dependent failure remains atomic. Use actual corrupted persisted naming references or structurally valid unresolved authored IDs, not a mocked return value. Retain failure evidence.

## UTF-8 contract correction

JSON Schema maxLength counts characters and cannot alone state native UTF-8 byte limits. Add explicit byte-limit metadata to shared schemas (512 bytes for edge/entity identifiers;65536 UTF-8 bytes for serialized definitions) and compile it into the standalone generated AJV validators using a narrowly scoped, browser-compatible keyword implementation in the existing generator. Keep ordinary maxLength too. Do not lower the character limit to128 or ASCII-only; existing valid Unicode IDs must remain valid. Do not advertise that unconfigured third-party JSON Schema validators understand the custom byte keyword.

Canonical commandJsonSchema must carry matching byte-limit metadata rather than a contradictory shape. Keep runtime canonical validation and generated protocol validation consistent. Exported standalone Source/Definition, nested GroupSummary/GroupResult/Result and snapshot validators must reject excessive-byte IDs even through nested definitions. Preserve strict unknown/private fields and source-kind/identity checks. Generator remains deterministic and no dynamic renderer eval is introduced. Use the installed AJV primary source to select its supported standalone-code keyword API; no remote lookup or server is needed.

Prove RED/GREEN with owner-qualified multibyte edge IDs and authored entity IDs: below512 bytes accepted, over512 bytes rejected despite fewer512 characters; nested result/snapshot paths reject too. Include total65536-byte definition boundary and existing delimiter-safe identities. Generated source/C# DTO shape stays driven by shared schema; no hand editing. The managed runtime typed query remains the next packet and must apply the same semantic byte checks when that query is added.
